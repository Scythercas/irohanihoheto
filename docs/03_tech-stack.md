## 2. ゲームエンジンの候補比較

本作は「テキストを読ませるノベルゲーム」の比重より、
**チャットUI・スケジュール画面・パラメータ表示といった"アプリのような画面"の比重が大きい**点が選定の鍵になる。

### 候補A: Ren'Py

| 観点 | 評価 |
|---|---|
| 費用 | 無料・商用可 |
| 学習コスト | 低〜中（独自スクリプト＋Python） |
| ADV基本機能 | ◎ セーブ／既読スキップ／回想／ボイス制御をすべて標準装備 |
| **Web公開** | **△ 対応はしているが、初回ロードが重くモバイルブラウザで不安定** |
| **カスタムUI** | **△ Screen言語で作れるが、チャットUIのような凝った作りは記述が煩雑** |
| 日本語 | ○ 実績多数 |
| itch.io | ◎ 定番 |

### 候補B: TyranoScript（ティラノスクリプト）

| 観点 | 評価 |
|---|---|
| 費用 | 無料・商用可 |
| 学習コスト | 低（タグベース。日本語ドキュメントが豊富） |
| ADV基本機能 | ◎ セーブ／回想／ボイスを標準装備 |
| **Web公開** | **◎ HTML5ネイティブ。ブラウザ公開が本来の形** |
| **カスタムUI** | **○ HTML/CSS/JSで拡張できる**。ただしエンジンの作法との噛み合わせに手間 |
| 日本語 | ◎ 国産。ふりーむ／ノベコレでの実績多数 |
| itch.io | ○ |
| 弱点 | 独自タグ言語のためGit差分管理・大規模化がやや苦しい |

### 候補C: Web自作（TypeScript ＋ React ＋ Vite）

| 観点 | 評価 |
|---|---|
| 費用 | 無料（GitHub Pages / itch.io とも0円） |
| 学習コスト | 中〜高（ただし**実装はClaudeが行う**） |
| ADV基本機能 | **× 全部自作**（セーブ、既読スキップ、回想、ボイス制御） |
| **Web公開** | **◎ そのままWeb。ロードも軽い** |
| **カスタムUI** | **◎ チャットUI・スケジュール画面は圧倒的に作りやすい** |
| 日本語・多言語 | ◎ テキストをJSONで外出しでき、D5（将来の多言語化）にも対応しやすい |
| itch.io | ◎ HTML5ゲームとしてアップロード可 |
| 弱点 | 工数が大きい。設計を誤ると破綻する |

### 候補D: Godot 4

Web出力可・無料だが、**ADV機能を一から作る点はCと同じで、かつWeb出力の容量が大きい**。
Unity未経験のユーザーにとって学習コストがCより高く、本作の利点が薄い。→ **不採用を推奨**。

## 3. Claudeの推奨

### 第一推奨: **候補C（Web自作: TypeScript + React + Vite）**

理由:

1. **本作の中心はチャットUI**（C6①・H3で「作り込む」と確定）。
   これはノベルゲームエンジンにとっては"例外的な画面"であり、Cなら最も素直に作れる
2. **週スケジュール制＋5色パラメータ**も同様に、UI比重が高くエンジンの型から外れる
3. **Web公開が主**（D3①）。Ren'PyのWebビルドは重く、体験版の離脱率に直結する
4. **実装はClaudeが行う**ため、「全部自作」の工数負担はユーザー側に直接かからない
5. テキストをJSON/YAMLで外出しでき、**シナリオとコードを分離**できる
   → ユーザーはシナリオファイルだけ触ればよく、D5（多言語化）にも効く

### 第二推奨: **候補B（TyranoScript）**

「自作は不安、実績あるエンジンに乗りたい」という場合はこちら。
日本語情報が豊富で、詰まったときに自力で調べやすいのが最大の利点。

## 8. T1 深掘り — エンジン選定の実質

### 8.1 「エンジンなら標準装備」は、本作でどれだけ効くか

| # | 機能 | Ren'Py / Tyrano | Web自作 |
|---|---|---|---|
| 1 | テキスト送り・文字速度 | ◎ 標準 | 自作 |
| 2 | 立ち絵・表情差分の切替 | ◎ 標準 | 自作 |
| 3 | 背景切替・フェード | ◎ 標準 | 自作 |
| 4 | BGM／SE／ボイス再生 | ◎ 標準 | 自作 |
| 5 | 選択肢 | ◎ 標準 | 自作 |
| 6 | セーブ／ロード（複数スロット） | ◎ 標準 | 自作 |
| 7 | オートセーブ | ◎ 標準 | 自作 |
| 8 | 既読管理・既読スキップ | ◎ 標準 | 自作 |
| 9 | バックログ（履歴） | ◎ 標準 | 自作 |
| 10 | オート再生 | ◎ 標準 | 自作 |
| 11 | コンフィグ（音量・文字速度） | ◎ 標準 | 自作 |
| 12 | 回想・ED一覧 | ◎ 標準 | 自作 |
| **13** | **LINE風チャットUI** | **自作** | **自作** |
| **14** | **週スケジュール画面** | **自作** | **自作** |
| **15** | **5色パラメータの管理・表示** | **自作** | **自作** |
| **16** | **カラットのプロフィール画面** | **自作** | **自作** |

**結論: 13〜16 はどのエンジンを選んでも自作になる。** そして本作は、
C6①・H3で「**メッセージ画面を作り込む＝ゲームの中心**」と決めた作品である。
つまり**エンジンの恩恵が最も薄いタイプの企画**。

さらに、13〜16 をエンジン上で作る場合は「**エンジンの作法に逆らって作る**」ことになり、
素のHTML/CSSで作るより手間が増える。Ren'Py の Screen 言語で
チャットのスクロールと吹き出しレイアウトを組むのは、CSSでやるより明確に面倒。

一方 1〜12 は**すべて定型**で、仕様が世の中に確立している。
つまり「自作＝未知の難問」ではなく、「**既知のものを書き写す作業**」に近い。

### 8.2 シナリオの書き味の比較（同じ1シーン）

**Web自作の場合（YAML）** — ユーザーが直接触るのはこのファイルだけになる

```yaml
- id: momoka_cafe_01
  bg: cafe_day
  bgm: bgm_daily
  lines:
    - speaker: 桃果
      sprite: momoka/smile
      voice: momoka_0012
      text: せんぱーい！こっちこっちー！
    - speaker: null            # 主人公の心の声（A5①で立ち絵・ボイスなし）
      text: （……声、でかいな）
  choices:
    - text: 何食べる？決めていいよ
      params: { confidence: -2 }   # 桃果は「決めてくれない男」が地雷
      next: momoka_cafe_02_bad
    - text: ここのパンケーキ、評判いいらしい
      params: { confidence: +3 }
      next: momoka_cafe_02_good
```

**Ren'Py の場合**

```renpy
label momoka_cafe_01:
    scene bg cafe_day
    play music bgm_daily
    show momoka smile
    momoka "せんぱーい！こっちこっちー！" voice "momoka_0012.ogg"
    "（……声、でかいな）"
    menu:
        "何食べる？決めていいよ":
            $ confidence -= 2
            jump momoka_cafe_02_bad
```

**TyranoScript の場合**

```text
[bg storage="cafe_day.jpg" time="1000"]
[playbgm storage="bgm_daily.ogg"]
[chara_show name="momoka" face="smile"]
[playse storage="momoka_0012.ogg"]
#桃果
せんぱーい！こっちこっちー！[p]
#
（……声、でかいな）[p]
[link target="*bad"]何食べる？決めていいよ[endlink]
```

**書き味に決定的な差はない。** Ren'Py も十分読みやすい。
差が出るのは **13〜16 の画面を作るとき**であり、そこはWeb自作が明確に有利。

### 8.3 【重要】「バイブコーディングで済ませたい」なら、Web標準一択

T6の「極力バイブコーディングで済ませたい」は、**技術選定を決定づける条件**。

- **TypeScript / React / CSS は、AIの学習データが最も豊富な領域**。
  生成コードの正確性が高く、そのまま動く割合が高い
- **Ren'Py（独自スクリプト＋Python）は中程度。TyranoScript（国産・日本語ドキュメント中心）は最も少ない**
  → AIが**もっともらしいが動かないコード**を出す確率が上がる
  → **デバッグはあなたの仕事になる。これはバイブコーディングの真逆**

つまり「エンジンを使えば楽」は、**人間が書く前提での話**。
**AIに書かせる前提では、むしろメジャーな技術のほうが楽になる**という逆転が起きる。

加えて T6 で **JS / HTML / CSS の業務経験**があると判明したため、
Web自作の学習コストは実質ゼロ。詰まったときに**中身を読んで直せる**のも大きい。

### 8.4 Web自作のリスクと対策（正直に）

| リスク | 対策 |
|---|---|
| 「全部自作」は**終わりが見えにくい**。機能を足し続けて完成しない | **体験版スコープを先に固定**し、`docs/05_milestones.md` に凍結する。1〜12を「最小実装」で先に通す |
| セーブデータの互換性が壊れやすい | セーブに**スキーマバージョン**を持たせ、マイグレーション関数を最初から用意する |
| ブラウザ差異（音声の自動再生制限など） | 音声は Howler.js を使い、初回タップで AudioContext を解錠する定石を最初から入れる |
| 個人開発で設計が破綻する | **シナリオ（YAML）とエンジン（TS）を完全分離**。シナリオを足しても実装は増えない構造にする |

### 8.5 提案する構成（候補Cを選んだ場合）

| 層 | 技術 | 理由 |
|---|---|---|
| ビルド | **Vite** | 高速。静的サイトとして出力でき、GitHub Pages / itch.io にそのまま置ける |
| 言語 | **TypeScript** | 5色パラメータや分岐条件を型で守れる。AI生成コードの事故が減る |
| UI | **React** | チャットUI・スケジュール画面のような状態を持つ画面に最適 |
| 状態管理 | **Zustand** | 軽量。ゲーム状態をまるごとJSON化できる＝**セーブ機能とそのまま直結** |
| 音声 | **Howler.js** | ブラウザの音声制限・フェード・多重再生を吸収 |
| シナリオ | **YAML**（ビルド時にJSON化＋型検証） | コメントが書ける。日本語が読みやすい。**Gitの差分が追いやすい** |
| スタイル | CSS Modules | 素のCSS知識がそのまま活きる |

**あなたが日常的に触るのは `scenario/*.yaml` だけ**になる構造にする。

### 8.6 それでもエンジンを選ぶべきケース

- 「動くものを最短で見たい。UIのこだわりは捨ててよい」→ **Ren'Py**
- 「日本語の情報が多い環境で、自分でも調べながら進めたい」→ **TyranoScript**

本作は C6①・H3 で**UIのこだわりを捨てない**と決めているため、上記には当てはまらないと判断する。

## 9. T5 — itch.io と GitHub Pages の役割の違い

**結論: 役割が違うので、両方使う。** 競合しない。

| | GitHub Pages | itch.io |
|---|---|---|
| 位置づけ | **開発・テスト用の常設URL** | **公開・集客用の作品ページ** |
| 更新 | `git push` で自動反映。**最速** | 手動でzipをアップロード |
| 発見される導線 | **ゼロ**（URLを知る人しか来ない） | **あり**（タグ検索・新着・おすすめ） |
| プレイヤーの反応 | 取れない | **コメント欄・評価・フォロワー** |
| 進捗の発信 | なし | **devlog**（開発日記）機能 |
| 配布形態 | ブラウザ版のみ | **ブラウザ版とダウンロード版を同時配布** |
| 課金 | — | 無料／投げ銭（Name your own price）を**後から切替可能** |
| 費用 | 0円 | 0円 |

### itch.io の具体的なメリット

1. **HTML5ゲームをページ内にそのまま埋め込める。** プレイヤーはインストール不要で即座に遊べる
2. **作品ページが名刺になる。** スクリーンショット・紹介文・タグを備えた体裁が最初から整う
3. **感想が届く。** 個人開発でモチベーションを保つ実質的な燃料になる
4. ~~D4①「完全無料」で公開しつつ、後から「投げ銭あり」に変更できる~~
   → **【2026-08-15 訂正】立ち絵の生成モデルが「生成画像の販売不可」のため、
   投げ銭への切り替えは行わない**（詳細は `docs/06_credits.md` §4）
5. **バージョン管理と配布が分離**され、開発版を人に見せずに済む

### 【提案】日本語作品なら、公開先をもう1つ検討したい

itch.io は**海外インディー中心**のプラットフォームで、日本語のみの作品（D5①）だと
届く相手が限られます。日本のノベルゲームプレイヤーの導線は別にあります。

| 追加候補 | 特徴 |
|---|---|
| **ノベルゲームコレクション** | ノベルゲーム専門。**ブラウザ版をそのまま公開できる**。本作と最も相性が良い |
| **ふりーむ！** | 国内最大級のフリーゲーム投稿サイト。プレイヤー数が多い |

→ **T7（新規質問）**: 公開先に**ノベルゲームコレクション／ふりーむ**を加えますか。
→ 推奨: **完成版のタイミングでノベルゲームコレクションに追加**（登録は無料）。

