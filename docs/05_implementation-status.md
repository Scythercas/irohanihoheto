## 3. シナリオYAMLの記法（早見表）

`src/scenario/*.yaml` に書く。**トップレベルはシーンの配列**。

### シーンの属性

```yaml
- id: momoka_date_01      # 必須。全体で一意
  screen: chat            # 省略時は adv。chat ならチャット画面で表示
  with: momoka            # screen: chat のとき必須。相手が変わると履歴がリセットされる
  bg: aquarium_evening    # 開始時の背景
  bgm: bgm_date           # 開始時のBGM
  next: schedule_hub      # 読み切ったあとに自動で進む先
  body: [...]
```

### body に書けるノード

| 書き方 | 意味 |
|---|---|
| `text: "..."` ＋ `who: mashiro` | セリフ。`who` を書かなければ**主人公の心の声**（A5①） |
| `face: smile` | 立ち絵の表情差分（素材が入ったら効く） |
| `voice: momoka_0012` | ボイスファイル名（拡張子なし） |
| `from: momoka` ＋ `msg: "..."` | **チャットの1メッセージ**。`from: iroha` なら自分の吹き出し |
| `at: "21:04"` | チャットの時刻を明示（省略時は自動で2分刻み） |
| `choice: [...]` | 通常の選択肢 |
| `reply: [...]` | **チャットの返信**。選んだ文が自分の吹き出しとして残る |
| `carat: match` ＋ `target: momoka` | **マッチング演出**のカード |
| `carat: profile` ＋ `target: momoka` | **プロフィール閲覧**のカード |
| `schedule: true` | **週スケジュール画面**に制御を渡す |
| `stage: none` / `stage: mashiro` | 立ち絵の相手を**明示的に退場／登場**させる |
| `bg: street_evening` | 背景切替 |
| `bgm: bgm_daily` / `bgm: null` | BGM切替／停止 |
| `se: se_notification` | 効果音 |
| `params: { confidence: 3 }` | 選択肢を経ずにパラメータを動かす |
| `flag: met_aoi` ＋ `value: true` | フラグ操作 |
| `goto: other_scene` | 別シーンへ飛ぶ |
| `branch: [...]` | **条件分岐**（下記） |

### branch（条件分岐）

上から順に評価し、**最初に条件を満たしたものへ飛ぶ**。
**最後の項目は必ず「条件なし＝それ以外」にすること**（どれも満たさないと走査が止まるため、検証で弾かれる）。

```yaml
- branch:
    - goto: mashiro_dere_01
      ifMetCount: 2        # 出会ったヒロインが2人以上（met_* フラグの数）
      ifTotalParam: 60     # 総合魅力レベル（5色の合計）が60以上
    - goto: mashiro_talk_plain   # それ以外
```

指定できる条件: `ifFlag` / `ifMetCount` / `ifTotalParam` / `ifParam: { confidence: 30 }` / **`ifEnding`**

`ifEnding` は終幕専用。しきい値の比較も優先順位も `engine.ts` の `endingRoute()` が行い、
シナリオ側は**結果の名前だけ**を書く。指定できるのは
`aoi` / `sui` / `touka` / `shion` / `momoka` / `mashiro` / `sad` の7つ。

```yaml
- branch:
    - goto: ending_momoka
      ifEnding: momoka
    - goto: ending_sad      # それ以外
```

### 立ち絵と表情

- **主人公の立ち絵は無い**（A5①）。**会話相手を画面中央に正面から**立たせる
  - 一時期、主人公を無彩色のシルエットで左に置いていたが、
    「顔のない人影が常駐する」画になったためユーザー判断で取りやめた（2026-08-15）
  - 誰の声かは、相手の立ち絵の**明るさ**で示す（相手が話す＝明るい／主人公が話す＝暗く引く）
- **メッセージウィンドウは立ち絵より必ず手前**。立ち絵は下端をマスクでフェードさせ、
  **ウィンドウに重なる範囲では消えている**。ここを浅くすると吹き出しの文字が読みにくくなる
- **背景が変わると、立っていた相手は自動で退場する**（場所替わり＝別れ、とみなす）
  - 同じ背景を指定し直した場合は続きの場面なので退場しない
  - 例外的に制御したいときだけ `stage: none` / `stage: <キャラID>` を書く
  - `npm run smoke` が「場所が変わったのに相手が立ったまま」を検出する
- 主人公はA5①により顔を描かない。**無彩色のシルエット**で置いている
- `face:` を省略したセリフは**直前の表情を引き継ぐ**
- 茉白の表情キー: `normal` / `bored` / `smug` / `laugh` / `fluster` / `away` / `smile`
- 立ち絵の差し替えは `src/ui/sprites/index.tsx` の `REGISTRY` に登録するだけでよい

### choice / reply の各項目

```yaml
- reply:
    - text: "日曜、水族館はどう。夕方から空いてる"
      params: { confidence: 4 }        # 5色パラメータの変動
      affection: { momoka: 2 }         # ヒロイン好感度の変動
      goto: chat_momoka_02b_lead       # 省略時は次のノードへ
      requireFlag: met_momoka          # このフラグが立っているときだけ表示
      who: momoka                      # 「誰についての選択肢か」。その子の色で縁取られる
```

**`who` は「相手を選ぶ」場面で必ず付けること。**
週スケジュールの「○○と会う」と同じ見た目になり、色で相手を見分けられる。
**並び順も `schedule.ts` の `SCHEDULE_ACTIONS` と揃える**
（青 → 翠 → 橙 → 紫 → 桃。場面ごとに順番が違うと、選ぶたびに読み直すことになる）。

**パラメータは 0 未満にならない**（`Math.max(0, ...)` で丸められる）。

## 4. 週スケジュールのイベント登録

デートイベントを増やすときは `src/game/schedule.ts` の `DATE_SCENES` に追記するだけでよい。
`progress[ヒロイン]` 回目に対応するシーンが再生される。

```ts
export const DATE_SCENES: Record<HeroineId, string[]> = {
  momoka: ['momoka_date_01', 'momoka_date_02'],  // ← 2回目を足す場合
  ...
};
```

**用意した本数を超えたら `EXTRA_DATE_SCENES[ヒロイン]`（「重ねの一日」）が何度でも再生される。**
ここをヒロイン共通の1シーンにしてはいけない。どの色も伸びなくなり、
「他の子に会う意味がない＝トレードオフが成立しない」という設計事故になるため、
ヒロインごとに分けて対応色が伸びるようにしてある。

**ここに書いたシーンIDは `npm run check:scenario` でリンク切れを検査している。**

## 6. 点数設計（バランスの根拠）

**この節と `npm run balance` は対で意味を持つ。** 片方だけ変えないこと。

| 項目 | 値 | 置き場所 |
|---|---|---|
| 行動枠の総数 | 12週 × 3枠 = **36枠** | `schedule.ts` の `FINAL_WEEK` / `SLOTS_PER_WEEK` |
| 個別ルートのしきい値 | 対応色 **80** 以上 | `constants.ts` の `THRESHOLD.INDIVIDUAL` |
| 茉白ルートのしきい値 | 5色すべて **45** 以上（かつ80未満） | `constants.ts` の `THRESHOLD.MASHIRO_ALL` |
| 書き下ろしのデート | 対応色 **+6**、選択肢の正解で **+6**（最良+12／最悪+4） | 各デートシーンの先頭 `params:` |
| 重ねの一日（`*_date_extra`） | 対応色 **+8** 固定（選択肢なし） | `dates.yaml` |
| 茉白への相談 | 5色すべて **+1** | `carat.yaml` |

**なぜこの値なのか（実測で決めた経緯）**

- 行動枠が **24（12週×2）では茉白ルートが数学的に到達不能**だった。5色すべてを45まで押し上げる余裕がない
- 個別のしきい値が60だと、茉白ルートの帯が `[45, 60)` と狭く、**均等に遊んだ人が意図せず個別ルートに落ちる**。80に上げて帯を広げた
- 茉白への相談が全色+2だと、**誰にも会わず相談し続けるだけで茉白ルートに入れた**。
  これは「5人と出会って色を得る」という作品の骨格（CLAUDE.md §3.3）を壊すので +1 に下げた。
  現在は、5人と会わなければどの結末にも届かない

**確認のしかた**

```powershell
npm run balance
```

デートシーンのYAMLから獲得点を**実測**し、行動枠の配分を総当たりして
7つのエンディングすべてに到達できることを検証する。到達不能なものがあれば異常終了する。
